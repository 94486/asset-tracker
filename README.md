# 数码资产持有成本管理系统

一个用于记录数码产品购入、计算每日持有成本、登记出售/损坏并分析折旧的本地桌面小工具。

- 数据完全本地化：SQLite 单文件存储，不依赖网络、不上传云端
- 双形态运行：打包 exe（单机桌面 + 系统托盘）或 Docker（局域网 Web 服务）
- 深色科技风界面：统一设计系统 + 线性 SVG 图标、玻璃拟态、分区信息架构、响应式与可访问性

## 快速开始

### 方式一：直接运行 exe（推荐）

双击运行 `dist/数码资产持有成本管理.exe`，会自动在浏览器打开（地址 `http://127.0.0.1:5678`）。
首次运行会在 exe 同级目录生成 `asset_tracker.db`（SQLite 数据库），所有数据都存在这里。

> 提示：如果浏览器没有自动弹出，手动访问 http://127.0.0.1:5678 即可。

**托盘图标**（仅 exe 模式）：

| 操作 | 功能 |
|---|---|
| 单击图标 | 打开浏览器页面 |
| 双击图标 | 打开浏览器页面 |
| 右键菜单 | 打开页面 / 退出程序 |

### 方式二：Python 源码运行

```bash
pip install -r requirements.txt
python app.py
```

服务启动在 http://127.0.0.1:5678，支持 Ctrl+C 优雅退出。

### 方式三：Docker 部署

详见 [DOCKER.md](DOCKER.md)，适合部署到服务器 / NAS 多设备访问。

## 功能

### 资产管理
1. **录入资产**：名称、品牌、分类、购买价格、购买时间、配置，支持任意「自定义选项」（字段名 + 值）。
2. **每日持有成本**：`购买价格 ÷ 已持有天数`，列表实时显示，按状态着色：
   - 使用中 → 绿色 `#3ddc97`
   - 已售出 → 金色 `#f5b942`
   - 已损坏 → 红色 `#ff6b6b`
3. **登记出售 / 损坏**：
   - 在弹窗内用「处理结果」分段选择明确 **已售出 / 已损坏**（不再依赖易误操作的原生确认框）；选「已售出」时才显示出售价格并做必填校验。
   - 已售出：填写处理日期 + 出售价格，系统计算 **最终持有成本 =（购买价 − 出售价）÷ 持有天数**，以及 **折旧 = 购买价 − 出售价** 与折旧率。
   - 已损坏：视为全额损失，最终持有成本 = 购买价 ÷ 持有天数。
   - 已处理的资产可随时「恢复」为使用中。
4. **强大表格**：
   - 列排序（点击表头切换升/降序）
   - 多条件筛选（状态 / 品牌 / 分类 / 关键词，搜索输入 160ms 防抖）
   - 表头吸顶 + 汇总行吸底（长列表滚动时列名与合计始终可见）
   - 汇总行（当前筛选结果的总投入、每日成本合计、盈亏合计）
   - 操作列图标化（处理/恢复为带图标主操作，编辑/删除为图标按钮 + 悬浮提示）
   - 名称前品类图标胶囊：常见数码品类（手机 / 平板 / 笔记本 / 显示器 / 耳机 / 手表 / 相机 / 键鼠 / 游戏 / 电视投影 / 音箱 / 充电电源 / 智能眼镜等）各有专属线性图标，未识别或空品类统一用通用图标
   - 行展开详情（配置、自定义字段、备注、折旧明细，带展开动画）
   - 智能空状态：区分「还没有数据」与「筛选无结果」，后者提供一键清除筛选
   - 右侧抽屉式录入表单，表格全宽显示
   - 数字列防溢出（超长自动省略号，布局稳定）

### 报表分析
> 报表页按「总览 → 智能洞察 → 趣味排行 → 数据图表」分区组织，信息层级更清晰。

- **统计卡片**（5 张，一行排布）：
  - 持有资产总额（仅使用中）
  - 总投入（历史累计）
  - 售出回血 / 最终损失（双数字卡片，绿 / 红双色）
  - 资产总数（按状态细分）
  - 当前每日持有成本合计（仅使用中）
- **智能洞察**（基于当前数据自动生成 3–5 条情境化提示）：
  - 按在用资产每日成本推算的年化持有开销
  - 当下最烧钱的在用单品
  - 折旧率 ≥ 60% 的高损耗预警
  - 售出盈利 / 几乎零损耗的保值亮点
  - 品牌 / 分类缺失的数据完整度提醒
- **趣味排行榜**（7 张，一行排布）：
  - 败家之王：历史总投入最高的资产
  - 最强钉子户：持有天数最长的资产
  - 跳水冠军：折旧率最高的资产
  - 性价比之王：每日持有成本最低的资产
  - 年度败家王：当年入手金额最高的资产
  - 最保值产品：售出后折旧率最低的产品
  - 最新入手：最近购买的资产
- **6 大图表**：
  - 每日持有成本排名（柱状图）
  - 资产折旧排行（含折旧率、最终持有成本）
  - 品牌投入分布（环形图）
  - 分类投入分布（玫瑰图）
  - 月度投入趋势（渐变柱状图）
  - 资产画像散点图（持有天数 vs 每日成本，点大小 = 价格）

### 数据导入导出
- **导出**：一键导出全部数据为 JSON（含版本、导出时间、记录数）或 CSV（可直接用 Excel 打开），保存到浏览器下载目录。
- **导入**：支持 JSON / CSV 文件，两种模式：
  - **追加导入**：保留现有数据，新增记录（按名称 + 价格 + 购买日期自动去重，重复跳过）
  - **覆盖导入**：清空现有数据后导入（导入前建议先导出备份）
- 导入完成后自动刷新资产列表与报表图表。

## 技术架构

- 后端：Python + Flask（`werkzeug.make_server`，无外网依赖）
- 数据库：SQLite（`asset_tracker.db`，持久化在数据目录）
- 前端：原生 HTML/CSS/JS + ECharts（本地离线加载）
- 托盘：pystray + PIL（仅桌面 exe 模式）
- 打包：PyInstaller（onefile 单文件，免安装 Python）

| `dist/` | 打包输出（exe 在此） | 每次打包生成；分发用 GitHub Release，不入库 |

## 数据存储与备份

- 所有数据保存在 `asset_tracker.db`（SQLite 单文件），**删除该文件即清空所有记录**。
- 数据库位置优先级：
  1. `DATA_DIR` 环境变量（Docker 卷挂载时）
  2. exe 同级目录（打包后） / 项目根目录（源码运行时）
- **打包自动保护数据**：`build.bat` 打包前会自动把现有数据库备份到临时目录，打包完成后恢复，**重新打包不会丢失或清空已录入数据**；无数据库时首次运行自动新建。
- 建议定期用「JSON 导出」功能备份数据，或直接复制 `asset_tracker.db` 文件。

## 重新打包

### 方式一：双击脚本（推荐）

双击 `build.bat`，自动完成 6 步流程：

```
[1/6] 检查 Python 环境
[2/6] 安装项目依赖
[3/6] 清理旧构建文件（备份并保留数据库）
[4/6] 执行打包（onefile 模式，约 1-3 分钟）
[5/6] 恢复数据库（沿用原有数据）
[6/6] 打包完成
```

产物在 `dist/数码资产持有成本管理.exe`。

> 打包失败也会自动尝试恢复数据库，数据万无一失。

### 方式二：命令行

```bash
pip install -r requirements.txt
python build.py
```

## 常见问题

**Q：重新打包会损坏已录入的数据吗？**
不会。`build.bat` 会自动备份并恢复数据库；exe 运行时读取的是 exe 同级目录的 `asset_tracker.db`，打包过程不会删除或覆盖它。

**Q：端口被占用 / 页面打不开？**
程序启动时会自动检测 5678 端口，发现旧进程占用会自动清理后重启。若手动访问无响应，检查是否有其他程序占用 5678 端口。

**Q：exe 模式下数据存在哪里？**
与 exe 同目录的 `asset_tracker.db`。如需迁移，把 exe 和 db 文件一起复制即可。

**Q：如何彻底删除数据？**
删除 `asset_tracker.db` 文件（建议先 JSON 导出备份）。

## 安全说明

- 服务默认只监听本机 `127.0.0.1:5678`，不对外网开放（Docker 模式除外，见 DOCKER.md）。
- 所有数据仅存本地，无任何上传、遥测或联网行为。
