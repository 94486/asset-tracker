## 四、缺陷清单

### P1-1（高）撤销删除接口不校验结算字段，可让列表与报表整页 500

**复现**

```bash
curl -X POST http://127.0.0.1:5678/api/products/restore \
  -H "Content-Type: application/json" \
  -d '{"name":"脏数据","price":10,"purchase_date":"2026-11-01",
       "status":"sold","sale_date":"not-a-date","sale_price":"abc"}'
# -> 200 {"ok":true}

curl -o /dev/null -w "%{http_code}" http://127.0.0.1:5678/api/products
# -> 500
```

**根因**

1. `restore_product()` 把 `sale_date` / `sale_price` / `list_date` / `list_price` **原样写库**，没有走 `parse_date` / `parse_money`；
2. `compute_cost()` 第 419 行直接 `net = price - sale_price`，遇到 TEXT 抛 `TypeError`；
3. 一个坏字段会让 `GET /api/products`、`/api/report/summary`、`/api/report/depreciation` 全部 500 —— 页面完全打不开，且 App 内无法自愈。

**影响**：正常前端不会触发（撤销只回传删除接口的返回值），但 Docker/局域网模式下任何能访问该端口的人都能一次性打挂；数据库被外部工具改坏也会出现同样结果。

**建议修复（两处，约 10 行）**

```python
# 1) compute_cost 入口做类型收敛
def _num(v, default=0.0):
    try:
        f = float(v)
    except (TypeError, ValueError):
        return default
    return f if f == f and abs(f) != float("inf") else default

price = _num(d.get("price"))
sale_price = None if d.get("sale_price") is None else _num(d.get("sale_price"))
list_price = None if d.get("list_price") is None else _num(d.get("list_price"))

# 2) restore_product 落库前校验
sale_price, err = parse_money(p.get("sale_price"), allow_blank=True)
if err:
    return jsonify({"ok": False, "msg": err}), 400
sale_date = parse_date(p.get("sale_date"))
list_date = parse_date(p.get("list_date"))
list_price, err = parse_money(p.get("list_price"), allow_blank=True)
if err:
    return jsonify({"ok": False, "msg": err}), 400
```

### P2-1（中）`/sell` 接受 `status=for_sale`，写出非法状态组合

**现象**：`POST /api/products/<id>/sell {"status":"for_sale","sale_date":"..."}` 返回 200，记录变成 `status=for_sale` 且带 `sale_date`、没有 `list_date` —— 违反「待售不应有结算字段」的不变量，报表里会被算作持有中，但详情页会走结算分支。

**根因**：`sell_product` 只校验 `status in VALID_STATUS`，而 `VALID_STATUS` 包含 `for_sale`。

**建议**：把该接口允许的状态收窄为 `("sold", "damaged", "in_use")`，转入待售只能走 `/list`。

### P3-1（低）请求体为 JSON 数组时接口 500

`POST /api/products`、`POST /api/wishlist` 传 `[1,2]` → `AttributeError: 'list' object has no attribute 'get'` → 500。

**建议**：统一取 body 的写法

```python
def json_obj():
    p = request.get_json(silent=True)
    return p if isinstance(p, dict) else {}
```

### P3-2（低）导入允许未来购买日期，与新增接口口径不一致

新增会拒绝 `purchase_date > today`，导入不会。导入未来日期后 `days_held` 恒为 0、`daily_cost` 变成全额价格，报表失真。

**建议**：批量插入前加一行 `if purchase_date > date.today().isoformat(): skipped += 1; continue`。

### 信息项：WAL 探针在测试环境回退到 delete

同目录 6 线程 × 20 次并发写会稳定出现 5 次 `attempt to write a readonly database`（测试沙箱的文件过滤导致），探针据此回退到 `delete`，行为**符合设计**。打包产物 `dist/asset_tracker.db` 实际为 `wal`，说明真实环境正常。此项不算产品缺陷，仅说明测试环境限制。
